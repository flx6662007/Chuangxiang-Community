# 产品范围

本文记录已讨论的产品边界和后续开发方向，不表示功能已经实现。实现进度见 [团队进度](progress.md)，接口状态见 [API 说明](api.md)。

## 服务对象

- 首期只做电脑端网页，在国豪书院试点，接受本校其他院系学生注册使用。
- 游客可查看资讯、快讯和不含联系方式的招募卡。
- 学生发布招募和提交申请前，须完成学校邮箱验证。
- 采用分类展示和固定招募模板，首期不设置开放式讨论区或站内聊天。

## 功能范围

| 模块 | 产品约定 |
| --- | --- |
| 资讯库 | 展示赛事与科研机会，支持筛选、收藏和排序，保留来源链接及更新时间 |
| 资讯同步 | 每 6 小时检查一次指定官方来源，支持管理员手动触发；来源是否可接入须逐项确认 |
| 快讯 | 管理员按需触发草稿生成，确认后发布，不设固定周期 |
| 参赛组队 | 固定模板招募、申请加入、授权查看联系方式及双方确认入队 |
| 账号 | 注册、登录、学校邮箱验证和操作权限控制 |
| 资源中心 | 第一版由管理员维护，不接受学生投稿 |
| 管理后台 | 内容维护、采集异常处理、举报核实与申诉处理 |

资讯同步尚未实现；当前没有爬取或导入赛事数据。每 6 小时是后续任务的计划周期。

## 组队规则

- 招募仅用于参赛，必须关联平台已收录的赛事及具体届次。
- 同一队伍同时只保留一张有效招募卡。
- 队长接受申请后开放双方约定的联系方式，此时不占用招募名额。
- 双方确认正式入队后才占用名额，同一用户在同一赛事届次只能正式加入一个队伍。
- 正式入队前可撤回申请；正式成员退出和移除按双方确认流程处理，具体状态和接口在开发该功能前补齐。
- 联系方式不包含在公开接口中。
- 平台内确认入队不等于完成赛事官方报名。

## AI 方向

优先评估两项应用：从官方通知中提取参赛条件和截止时间等字段，并保存原文依据；根据已收录且仍有效的信息生成快讯草稿，由管理员确认后发布。

Qwen 托管 API 是试用候选，最终模型依据实际样本的准确性、响应时间和费用决定。模型输出需经过格式、来源依据和业务规则校验。模型不直接决定账号权限或入队结果。

卡片模板由前端预先编写，已发布内容保存在数据库。普通列表读取已有数据，不等待 AI 生成卡片。AI 异常时应保留已有资讯浏览和基础组队能力。

自然语言赛事检索、队伍匹配和向量检索属于后续评估方向，尚未确定进入首版。
