# 前端实施方案

更新日期：2026-09-26。本方案根据参考 UI 调整页面组织和开发顺序。现有首页、赛事列表、赛事详情、账号页的视觉改版和 404 已在本地实现；团队广场等新增业务属于待实现方案。业务规则以 [产品范围](product-scope.md) 为准，已开放接口以 [API 说明](api.md) 为准。

## 1. 栏目与范围

保留参考图的浅色背景、卡片布局、分类筛选和清晰的主导航，采用现有名称“创享平台”。首期只做电脑端网页。

| 参考 UI | 调整后的内容 | 阶段 |
| --- | --- | --- |
| 首页 | 赛事搜索、最新收录赛事、已完成栏目入口、管理员联系方式 | M1 |
| 赛事中心／信息中心 | 统一叫“赛事中心”；搜索、分类、分页、详情和官方来源 | M1 |
| 团队广场 | 仅展示与已收录赛事具体届次关联的招募卡；不开放自由项目招募 | M1 |
| 发布招募 | 选择赛事并填写固定模板，不提供自由帖子编辑器 | M1 |
| 个人中心 | 复用现有账号页，增加我的组队与必要系统通知 | M1 |
| 创享资讯 | 科研机会＋快讯两个页签，复用 `research`、`newsletters` 的业务范围 | M2 |
| 校园服务 | 改名“资源中心”，展示管理员维护的学习、竞赛资料及外链；不提供校园行政服务 | M2 |
| 收藏 | 登录用户收藏及失效占位；接通接口后再显示书签和我的收藏 | M2 |
| 智能助手 | 有来源依据的赛事查询与摘要，评测通过后开放 | M3 |
| 404 页面 | 路由不存在时提示返回首页或赛事中心 | M1 |

导航只展示已经完成且可访问的栏目。当前保留首页、赛事中心、我的账号；团队广场达到相应开发验收后加入。资讯、资源、AI 不提前放置空白入口。

参考图中的“200+ 赛事”“5000+ 学生”“合作机构”、热度、阅读量和排名没有真实依据，首版不展示。首页使用“最新收录赛事”，不使用“热门赛事”。“我的参赛事项”改成“我的组队”，平台无法证明用户已完成官方报名。

## 2. 技术与现有基础

继续使用 **Vue 3＋JavaScript＋Vite＋Vue Router＋Axios＋Element Plus**，暂不增加 TypeScript、Pinia 或另一套 UI 框架。页面状态先用 Vue 的 `ref`、`computed` 和可复用组合函数；有实际跨页共享需求时再评估状态库。

| 已有文件或能力 | 本轮处理 |
| --- | --- |
| `src/layouts/AppLayout.vue` | 统一导航、页面宽度与账号入口，后续增加系统通知入口 |
| `src/views/WelcomeView.vue` | 从欢迎页改为首页，复用赛事列表数据，不做全站搜索 |
| `CompetitionListView.vue`、`CompetitionDetailView.vue` | 保留已有搜索、分页、加载与异常处理，调整布局并补分类 |
| `src/components/CompetitionCard.vue` | 继续使用统一卡片组件，调整展示层级 |
| `src/views/AccountView.vue` | 保留登录、学校邮箱核验与本人联系方式维护，增加我的组队入口 |
| `src/api/http.js`、`accounts.js`、`competitions.js` | 继续集中处理请求，不在各组件重复写 API 地址和认证逻辑 |
| `src/utils/competition.js`、`account.js` | 复用日期、外链、账号状态处理，不重新实现一套 |

赛事卡片和招募卡片都是预先编写的 Vue 组件。打开页面时读取数据库已有内容，填入组件即可；不等待爬虫或 AI 现场制作卡片。

## 3. M1 页面

### 首页

- 顶部搜索只搜索赛事，提交后进入 `/competitions?search=关键词`，输入框明确写“搜索赛事名称、主办方或关键词”。
- 展示最近发布的公开赛事和可用栏目入口。默认沿用当前接口的最新发布顺序，不把重复采集时间当成发布时间。
- 暂无内容时显示说明和赛事中心入口，不用虚构数据填满页面；演示样例继续明确标注。
- 背景图只使用团队有权使用的素材；无合适素材时用纯色或简单图形，不依赖截图中的校景和赛事标识。

### 赛事中心与详情

- 列表：赛事名、届次、分类、标签、主办方、已知截止时间和官方来源；已有搜索和分页继续保留。
- 分类筛选复用后端现有 `category` 参数。分类选项需由后端提供完整字典后接通，不从当前分页的 20 条记录推断全部分类。
- 首版不直接照搬“报名中／进行中／即将开始”标签。当前数据不足以判断所有状态；`is_recruitment_open` 只表示平台允许招募，不能替代赛事报名状态。
- 详情分为赛事介绍、参赛要求、时间安排、校内安排、官方来源；字段缺失显示“未注明”，不补造内容。
- 截图的“立即报名”改成“查看官方报名信息”，跳转已核验的官方链接。平台不接收赛事报名，不显示站内报名成功。
- 团队广场可用后，详情增加“查看本赛事招募”，带上赛事 ID；是否可发布由后端根据赛事和账号条件判断。
- 首版不做讨论区、赛程图、奖项图表、资料下载库。已有文本按文本展示；M2 可接入资源中心中与赛事关联的资料。

### 团队广场与招募详情

- 展示名称固定为“团队广场”，页面说明“查找同一赛事的参赛伙伴”。业务仍是参赛组队。
- 卡片标题由“赛事名／届次＋所需角色标签”生成；没有角色时显示“参赛招募”。不新增自由团队名称或自由简介字段。
- 卡片显示赛事、所需角色／技能、基础要求、每周投入、协作方式、剩余名额、真实到期时间及最后编辑时间；未知或未选择项使用明确空态。
- 优先实现赛事、角色、技能、协作方式筛选。筛选参数及字典接口先与后端约定，不在前端对当前分页结果做假筛选。
- 不按“已组队”判断招募结束：接受申请不等于入队，满员也不等于卡片关闭。展示后端计算的可申请状态、剩余名额及原因。
- 游客可以阅读公开卡片。公开响应必须完全不含联系方式，不能先下载到浏览器再用 CSS 隐藏。
- 详情展示固定模板、赛事原文和申请入口。申请前说明：“招募者接受后，双方将看到彼此约定的联系方式；沟通后仍需双方确认入队。”

### 发布与编辑

| 表单项 | 规则 |
| --- | --- |
| 所属赛事及届次 | 必选，限定已收录且允许招募的赛事；编辑时不可随意改换 |
| 申报已有成员数 | 必填，含招募者本人；与平台已识别成员及赛事人数上限共同校验 |
| 本轮计划招募人数 | 首次发布至少 1；编辑不能低于本卡仍占名额的成功入队人数 |
| 团队已有能力、所需角色、所需技能 | 选填多选，使用管理员维护词库；不允许随意新增文本标签 |
| 基础要求、每周投入、协作方式 | 必填单选，使用已确认枚举 |
| 合作目标、预计合作时长 | 选填单选 |
| 校区 | 线下或混合协作必填多选；线上协作不填写 |
| 招募有效期 | 仅选 3／7／14 天，发布前展示后端计算的实际截止；不提供任意日期选择器 |

不保留截图中的自由“项目简介”“其他要求”和手填截止时间。选项文案及枚举以 [正式字段表](remaining-fields-table.md) 和 [字段说明](database-fields.md) 为准。

编辑同一张卡保留卡片编号，由后端保存新版本。提交前提示变更会通知相关用户、挂起未完成申请；编辑不延长有效期。后端返回版本冲突时，先读取最新内容并提示重新核对，不静默覆盖。

### 我的组队与通知

- “我的组队”区分我发布的招募、我提交的申请、我的正式队伍。招募者称为“招募者”，不默认称现实队伍队长。
- 申请表只填写选填意向角色、选填已有技能和必填每周可投入时间；不增加自我介绍或附件。
- 显示“待处理 → 已开放联系方式，待双方确认 → 已正式入队”及撤回、拒绝、结束等结果，不用一个“已通过”混淆状态。
- 招募变更时展示变化字段，提供“按最新条件继续申请”或“撤回”；读过通知不视为同意，旧确认不能沿用。
- 私人联系方式只通过授权接口取得；申请结束等导致授权失效时清除当前页面中的联系方式并刷新权限。
- 完整阶段补齐撤销本人入队确认、结束已接受申请、退出／移除、解散、24 小时处理结果及历史记录。按钮由后端对象状态和允许操作决定。
- 通知只显示系统业务消息和未读标记，不建设私信聊天。点击通知后读取最新对象状态，不能把旧消息当成当前权限依据。

## 4. 路由与接口交接

下表的“拟新增”是页面路由建议，不表示存在相应后端接口。开发前由前后端共同确认字段、权限、错误码，再更新 `api.md`。

| 页面路由 | 当前状态 | 数据需求 |
| --- | --- | --- |
| `/` | 已有，新视觉已在本地实现 | 复用公开赛事列表展示最新 4 条，首版不建首页统计接口 |
| `/competitions` | 已有 | 现有 `GET /api/v1/competitions/`，补分类字典支持 |
| `/competitions/:id` | 已有 | 现有 `GET /api/v1/competitions/<id>/` |
| `/account` | 已有 | 复用现有账号 Session、本人资料与 CSRF 接口 |
| `/teams` | 拟新增 | 公开招募列表、筛选字典与分页 |
| `/teams/publish` | 拟新增 | 可选赛事与模板字典、发布预校验和创建招募 |
| `/teams/:recruitmentId` | 拟新增 | 公开详情；登录后读取本人申请状态与允许操作 |
| `/account/teams` | 拟新增 | 本人招募、申请、成员关系及相应业务操作 |
| `/account/notifications` | 拟新增 | 本人系统通知列表、未读数量与标记已读 |
| 未匹配路径 | 已在本地新增 | 404 页面，提供首页与赛事中心入口，不依赖后端业务 API |

拟新增文件按职责组织：页面放 `src/views/`，`RecruitmentCard.vue` 等复用组件放 `src/components/`，请求分别放 `src/api/teams.js` 与 `notifications.js`，枚举展示和状态文案放 `src/utils/`。只在开始对应步骤时创建文件，不提前堆积空目录。

浏览器继续通过同源 `/api` 代理访问后端。写入使用现有 Session Cookie 和 CSRF；暂停真实 SMTP 不等于取消身份验证。开发使用已有账号流程及控制台验证码，不能在前端伪造已核验状态或公开绕过权限的开关。

## 5. 通用页面状态

| 场景 | 页面处理 |
| --- | --- |
| 加载中 | 显示骨架或加载提示；阻止重复提交，但不把按钮禁用当成后端校验 |
| 列表为空 | 区分暂无公开内容与筛选无结果，提供清空筛选入口 |
| 记录失效或下架 | 显示不可用及返回入口；私有历史按后端授权展示，不泄漏非公开信息 |
| 请求失败 | 保留可修改输入，提供手动重试；不自动重放发布、确认入队等写操作 |
| 会话失效 | 提示登录并保留可安全恢复的表单输入；不保存密码或联系方式到本地存储 |
| 并发冲突、满员、条件变更 | 显示后端原因，刷新最新状态；不能仍提示操作成功 |
| 到期与 24 小时时限 | 展示服务端返回的截止时刻；前端倒计时仅作提示，最终结果由后端裁定 |

请求取消及防止旧响应覆盖新结果，沿用现有赛事页实现。搜索和筛选写入 URL，返回列表时保留条件；未知时间不补造时刻。文本安全渲染，外链只允许 `http`／`https`。

## 6. 交付顺序

### M1：赛事与组队

| 步骤 | 前端交付 | 验收边界 |
| --- | --- | --- |
| 1. 浏览演示 | 首页和赛事中心改版、公开团队广场、固定模板表单样式、404 | 可用样例联调，样例与未接通操作明确标注；不对真实学生开放申请 |
| 2. 业务闭环 | 接通发布、申请、接受联系、双方确认入队、我的组队、必要通知 | 两个测试账号完成整条流程；游客响应无联系方式；此时仍为受控开发测试 |
| 3. 完整状态 | 接通编辑挂起及重确认、撤回／终止、到期／满员／关闭、退出／移除／解散及权限变化 | 连同后端检查并发、时间边界和失效授权；必要账号核验与实际部署条件就绪后，才开放真实学生使用 |

无需为页面换色单独补一套测试；对关键状态转换、隐私显示与错误恢复增加有实际意义的检查。每步与后端按相同样例联调，结果写入团队进度，不能把样例交互记为业务已实现。

### M2：资讯、资源与收藏

- 创享资讯只整合科研机会与已发布快讯，不按截图新建赛事新闻、人物专访、校园动态等投稿栏目。
- 科研详情保留招募主体、官方信息链接及原文说明；不把科研机会转成平台内自由组队。
- 快讯展示发布版本、来源和更新时间；内容变化或来源失效按后端标记提示。
- 资源中心以管理员维护的名称、分类、说明、外链展示，不接学生投稿和任意附件上传。
- 收藏接通后再开放书签。已收藏内容下架时显示不可用占位，不泄漏下架正文。

### M3：智能助手

- 先提供“按条件查赛事”“概括当前赛事要求”两个入口；答复附已收录赛事和官方来源链接，注明信息时间。
- 无依据时明确无相关信息；AI 调用失败仍能使用普通赛事搜索，不生成不存在的来源或名额。
- 浏览器只调用后端，不持有模型密钥。页面不让模型代替用户发布、申请、正式确认或决定账号权限。
- 不承诺“最佳队友”“智能自动组队”。先用真实通知样本验证摘要和检索质量，再开放助手入口。
