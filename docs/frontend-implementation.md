# 前端实现说明

## 本轮完成

原有蓝白界面与赛事、账号逻辑继续保留。新增团队广场、模板发布与编辑、招募详情、我的组队和系统通知；赛事分类使用完整字典，详情可按具体届次进入组队。页面直接使用 Django 业务接口，没有用模拟接口代替真实动作。

## 如何实现

1. **先对齐合同。** 以 `api-teams.md` 为准，招募读值为平铺对象，多选返回 `{code,name}`；写入仅传 `code`。前端不自行添加自由文本字段。
2. **按职责拆代码。** Axios 请求在 `api/`，状态和表单转换在 `utils/teams.js`，页面在 `views/`，申请与队伍操作在复用组件中。新增路由按需加载，不增加框架。
3. **发布分两步。** 固定模板先请求后端预校验，展示真实有效期；本人明确确认后才保存。编辑带看到的卡片版本，冲突时停止提交，由用户读取最新内容后再核对。
4. **状态由后端决定。** 按 `allowed_actions` 展示按钮；每次写操作仍由服务端重验。申请动作同时提交当前卡片和申请资料版本。接受联系、正式入队分开显示，变更后不复用旧确认。
5. **联系资料单独授权。** 普通公开与申请对象中不塞联系方式；点击查看才调用受控联系接口。开始其他动作、权限失败、失焦、离页或 30 秒到期均清空显示，未完成响应通过请求代次防止重新填入旧资料。
6. **保留错误和历史。** 取消旧列表请求并丢弃过时响应；变更后继续、拒绝、结束、退出、移除、解散均有说明和明确确认。错误具体到业务字段，操作反馈保留在父页面，刷新不会吞掉失败原因。
7. **沿用历史选项。** 停用词条仍显示旧值且可以移除，但不能重新选择为新项。编辑已有成员数以服务端当前有效基数初始化，避免把已退出成员误补回申报人数。

## 验证边界

本轮执行前端单元测试和生产构建；双账号浏览器联调、PostgreSQL 并发和采集结果由总进度单独记录。没有把编译成功写作公网可用。真实 SMTP、公网部署、资讯资源和 AI 助手继续属于暂缓范围。

## 举报与申诉

- 赛事、招募详情增加举报入口；账号中心进入“我的举报与申诉”。仅登录即可使用，不以邮箱核验、联系方式或新增发布资格拦截。
- 原因采用后端固定词表，说明限制为 1～1000 字，不上传附件。本人记录展示处理状态、反馈与实际执行说明；举报不会直接下架内容。
- 申诉从服务端分页返回的本人账号限制、招募处置、已处理举报中选择；页面不接受任意对象编号。已有待处理申诉时不能重复提交。
- 登录、退出和密码重置成功后广播无身份数据的会话变化标记。隐藏标签、离页、换号或退出立即清空治理内容并取消请求，过时响应不能回填。回到标签页重新检查服务端会话。

## 首页编辑栏目

“创享快讯”由团队在 data/editorial.js 手动维护，无内容时显示首期筹备空态。“本科科研机会”仅展示核验过的官方实验室线索，区分原文日期与核验日期，注明不保证当前名额；外链仅接受 HTTP(S)。不增加自动科研采集或虚构项目。
