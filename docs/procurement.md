# 资源与费用清单

当前决定：先做**零付费、本机可演示的开发版本**，使用现有电脑完成网页和接口联调；邮箱验证码在开发终端查看。当前不购买服务器、域名、发件服务或模型额度。真实 SMTP、公网部署和 Docker 运行尚未验证。

## 必要能力

“必要”指对应阶段需要具备该能力，不等于必须购买独立产品。

| 能力 | 用途与启用阶段 | 当前安排 | 后续费用影响 |
| --- | --- | --- | --- |
| 本地开发环境 | 现在编写、运行和演示前后端与数据库 | 现有 Windows 电脑、Python、Node.js、PostgreSQL | 当前无需新增服务费；人员时间、电力和设备仍是资源成本 |
| 持续运行主机 | 对外开放时运行网页、后端、数据库、缓存 | 仅准备 Linux 部署配置，未获得主机 | CPU、内存、磁盘、带宽、地域、计费周期 |
| 访问地址与 HTTPS | 对外开放时提供可访问地址并加密登录请求 | 未配置域名或证书 | 自购域名涉及注册和续费；通常无需购买商业证书 |
| SMTP 发件 | 开放学校邮箱注册时真正投递验证码 | 本地控制台模拟邮件；不能验证真实邮箱归属 | 发送量、速率、发件身份及服务额度 |
| 备份与恢复 | 开始保存真实用户数据前，准备故障恢复 | 提供备份恢复步骤，未进行生产恢复演练 | 数据容量、保留期、异地存储及流量 |

## 可免费替代的资源

| 资源 | 可替代的购买项 | 使用前确认 |
| --- | --- | --- |
| 学校已有服务器 | 新购云服务器 | 获准运行网站、访问范围、运维负责人、资源限额；内网主机不一定能公网访问 |
| 学校或团队已有域名的子域名 | 新购域名 | 获准使用、DNS 配置权限及维护归属 |
| 支持免费证书的公共 CA | 商业 HTTPS 证书 | Caddy 申请条件、域名解析和外部连通性满足要求 |
| 学校批准的发件服务 | 新购邮件服务 | 允许程序发信、SMTP 配置、限额及实际收件效果 |
| 邮件服务商的免费额度 | 小规模试点的部分发信费用 | 免费期、每日/每月额度、SMTP 端口、续期和超额规则；尚未选定服务商 |
| 学校备份空间或团队受控设备 | 初期异地备份服务 | 权限、加密、异地副本及恢复演练；同一服务器的另一目录不能替代异地备份 |

申请这些资源并不等于已获批准。只有资源实际可用、部署验收和真实邮件测试均完成后，才可称为面向同学开放的试点。

## 后续可选项

| 项目 | 用途与启用阶段 | 当前替代 | 费用由什么决定 |
| --- | --- | --- | --- |
| AI 模型服务 | 核心网页完成后，接入通知提取、快讯草稿 | 离线响应测试；不声称已完成真实 AI，默认关闭外部调用 | 输入输出 token、调用频率、模型单价 |
| 托管数据库、托管 Redis | 规模或运维需要增加时减少自行维护 | 试点可先运行在同一服务器的容器中 | 实例、存储、备份及可用性 |
| 对象存储、CDN、付费监控 | 出现附件、加速、长期告警需求后启用 | 当前未开放学生附件上传，先使用日志及人工检查 | 文件、访问量、日志保留及监控频率 |
| GPU 或专用 AI 服务器 | 以后确定必须自托管模型且资源不足时再评估 | 当前不训练模型，也不要求自托管大模型 | 显存、运行时长、存储与运维；不属于本轮采购 |

## 零新增服务费的推进顺序

1. 先在现有电脑完成自动化测试和人工验收；控制台邮件用于开发，不对真实用户宣传为学校邮箱验证服务。
2. 向学校确认已有服务器、可用子域名和获准使用的发件账号。三项资源满足后，按 `deployment.md` 部署并进行真实投递测试，可实现无需新购买云服务的小范围试点。
3. 如无法获得资源，再比较云服务器、域名及 SMTP 的实际报价，写明免费期、续费价、额度和停止付费后的数据处理方式，由团队确认后采购。
4. 保存真实用户数据前落实异地备份。AI 按需要和预算另行启用，不作为赛事列表浏览的前置条件。

“免费托管”不自动等于适合此方案：需要同时确认是否持续运行、是否保留数据库、能否向 SMTP 端口发信、是否支持后台服务和持久卷。本清单没有选定某个免费云托管服务，也没有用临时免费额度承诺长期可用。

## 采购时记录

若学校无法提供资源，可按下表询价；这是小规模试点的起步规格估算，尚未经目标服务器压测，不是已选商品或已报价订单。

| 采购项 | 数量与起步规格 | 何时需要 |
| --- | --- | --- |
| Linux 云服务器 | 1 台，2 vCPU、4 GB 内存、50 GB SSD；支持 Docker 和持久磁盘，允许 HTTPS 与出站 SMTP；先按月验证 | 准备集中对外试点，且没有获准使用的学校主机时 |
| 域名 | 1 个普通域名，确认续费价格和 DNS 管理权；已有合适子域名则不买 | 确认部署地址后 |
| SMTP 发件服务 | 1 个项目发件身份；试点先询问每天约 100 封的配额、速率限制、学校邮箱投递效果及超额计费 | 准备让真实用户自助验证时；100 封是预算起点，不是已测需求 |
| 异地备份空间 | 1 处受控存储；容量按数据库大小、保留份数与增长量确定 | 保存真实用户数据前 |
| AI API 额度 | 暂不购买；小样本评测后按实际 token 消耗申请额度并设置限额 | 确定模型并接入业务后 |

HTTPS 证书、PostgreSQL、Redis 不列为必须单独购买的产品；当前部署方案使用免费证书与自行运行的软件。服务器费用仍需包含磁盘、流量和备份的实际账单。

每项填清：服务商及产品、资源归属账号、管理员、地域、月/年费用、免费到期日、续费日、流量/发信额度、数据导出办法、取消方式。域名和邮箱账号应归团队或授权部门管理，避免依赖毕业成员个人账号。

先按 **服务器 + 域名/子域名 + SMTP + 备份** 估算基础费用；若全部已有且获准使用，新增服务支出可以为零。没有实际报价前不写总价，也不把开发同学无偿参与理解为系统没有维护成本。

相关能力依据：[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)、[Docker 生产部署](https://docs.docker.com/compose/how-tos/production/)。具体云服务及邮件额度以后按选定服务商的官方定价与限制核实。
