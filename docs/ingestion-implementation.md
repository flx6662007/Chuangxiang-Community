更新：2026-09-26。代码入口是 `backend/ingestion/`，不是页面打开时执行的爬虫。本说明记录实现与运行方法；本机正式库的实际导入、调度启用和 GitHub 合并状态以 [团队进度](progress.md) 为准。

## 卡片内容如何补全

文章正文使用 `.article-content`；标题和原通知发布日期从专用标题/元信息区读取。导航、页脚、相关文章不能成为年份、主办方、资格和人数依据。

| 字段 | 处理方式 |
| --- | --- |
| 赛事名称、年度/届次、季节 | 以文章标题为准；数维杯春季和秋季分别建档 |
| 主办方、资格、人数 | 只提取正文中的明确条款；指导教师人数不计入学生人数 |
| 简介、详情、赛题方向 | 由已提取事实生成简短说明，保留方向、资格和报名方法；公开页面不复制整篇公告 |
| 报名和作品截止日期 | 只采用包含明确年月日的对应条款；没有日期保留 `null` |
| 截止时刻、时区 | 官网未明确时区时不填写精确时间字段，原文小时保留在 `deadline_notes`；不能自动补成 23:59:59 |
| 报名入口 | 数维杯从正文核验外链，AIC 从其官方导航的“报名”链接取得并标注链接证据；不访问报名系统、不代用户付款或报名 |
| 分类 | 使用适配器维护的人工智能/数学建模分类，是平台栏目分类，不冒充官方奖项等级 |
| 校内安排、未知字段 | 没有校内来源就留空；前端显示“官方通知未注明”或对应空态 |

`--enable-recruitment` 是单独的平台政策：只对**新收录**且已明确可组队、人数上限和未来报名日的赛事启用招募。平台按北京时间在官方报名截止日期前一天 00:00 提前停招，依据写入内部 `recruitment_note`；这不等于官方报名截止时刻。已收录赛事的人工停招不会被下一次同步自动打开。

### NCDA 日期与人数口径

- 正文使用 `#main .dsjs` 内的 `table.peixun_table`，按标签读取，并处理 `rowspan` 合并行。年度取正文赛事横题/赛项名称，不取页脚、图片文件名或抓取日期；编码包含年度及赛项代码。
- 9B6、9B8、9C3 的原文分别给出 **2026-09-30、2026-09-22、2026-10-31** 作品投稿截止。只写 `submission_deadline`，独立报名截止保持空。省赛征稿、学校审核、获奖公布、国赛阶段分别保留，不把后续阶段日期当初次投稿截止。
- 首页“征稿中”仅用于发现链接，不能覆盖详情中的已过截止日期；9B8 已于 9 月 22 日截止。已收录页面即使离开首页征稿栏目，仍由既有复查机制持续跟踪。
- “每件作品最多三名作者”保留为作品作者限制；不自动当作队伍人数上限，教师人数也不计入队员。明确允许个人/团队的页面记录参赛形式，但这三项暂不自动开启组队招募。
- 正文未注明发布日期、时区、独立报名截止时保留缺项。不会把采集日期写成发布日期，也不设置虚构的截止时刻。
- 新增 NCDA 不升级现有全局 `v2`，避免为 AIC、数维杯同一原文重复制造候选。

## 处理链路

```text
手动命令 / 每 6 小时调度
  → 读取启用的白名单来源
  → 来源级互斥，发现新通知、轮换复查最久未成功获取的已收录通知
  → FetchRun 获取记录
  → SourceVersion 不可变原文版本
  → ProcessingResult 字段候选、证据、缺项和校验结果
  → 受控规则或管理员采纳
  → 赛事统一事务服务 + 已核验来源
  → 前端从数据库读取卡片和详情
```

- 相同来源、URL 和规范化正文哈希复用版本；只更新最近获取时间，不刷新原通知日期、首次发布时间或赛事内容更新时间。
- 正文变化创建新版本，旧版本不覆盖。采纳赛事和标记候选在同一短事务内提交；失败整体回滚。
- 官网 A→B→A 回退时复用原文版本 A，但新增待复核的处理记录，不复用历史采纳决定。采纳前核对最近观察版本，旧候选不能覆盖新信息。
- 官网复用同一 URL 发布新年度/新届次时，候选保持待处理，人工与规则采纳都不能把原赛事改成新届次。管理员须独立建新届次并核对来源关联，保留旧届次及其队伍历史。
- 自动采纳保存规则版本 `official-html-2026-09-v2`。新记录须有明确身份、主办方和资格依据；人数或日期未知的记录不会自动开启招募。升级规则会为相同原文产生新的候选，复用原文版本；已发布赛事的重要字段补全仍须复核。
- 已有记录只允许尚未被人工修改的说明性字段自动更新。日期、人数、资格、报名链接等重要变化进入待复核，保留当前公开内容；原文缺失或网络失败不清空旧赛事。
- 管理员采纳重要变化会停止该赛事招募，并通过统一赛事服务结算受影响申请；重新核对条件后再开启。
- 同一截止条款出现多个日期或延期/调整措辞时标为待复核，不直接取第一个日期；人数必须明确属于参赛学生/队员，教师人数与学生人数混合且无法区分时停止自动采纳。
- AIC 的“每支团队成员上限 3 名”明确计入队员人数，“最多 2 名指导教师”单独排除。只有明确允许单人时才记为个人/组队均可、下限 1 人；多组别给出不同上限时留待复核。同校/跨校等限制随参赛条款保留，不能只留下人数。
- 代码使用 PostgreSQL 连接级 advisory lock；同来源重复触发直接跳过，进程退出后锁自动释放。异常退出留下的 `running` 记录仅在下一进程成功取得同一来源锁后标记中断。

## 手动运行

在 `backend` 目录、数据库可用且已有获授权管理账号时执行。将下列 `管理员ID` 替换为实际数字；不要把密码写进命令或仓库。

```powershell
# 第一次：登记内置来源、采集、受控发布、对有明确依据的新赛事开放内部招募。
.\.venv\Scripts\python.exe manage.py sync_competitions --init-sources --actor-id 管理员ID --trigger manual --auto-accept --enable-recruitment

# 之后：全部启用来源，沿用各来源维护人的权限；适合任务计划。
.\.venv\Scripts\python.exe manage.py sync_competitions --trigger scheduled --auto-accept --enable-recruitment

# 只检查一个来源，最多 10 篇文章，不自动采纳。
.\.venv\Scripts\python.exe manage.py sync_competitions --source aicomp --actor-id 管理员ID --trigger manual --max-pages 10
```

默认每来源最多 20 篇，可选 1–50。命令返回每个来源的发现、获取、未变化、采纳、待处理、失败数量及锁竞争状态。发生实际失败时以非零退出码结束，同时保留已成功处理的其他页面。初始化不会覆盖已有配置、维护人或重新启用被停用来源。

现有部署升级后，可用 `--init-sources --source ncda --actor-id 管理员ID --trigger manual --auto-accept` 单独登记、采集 NCDA；已有 AIC/数维杯配置不会重置。之后默认的定时命令会覆盖全部启用来源。

管理员在 Django Admin 中查看 `SourceConfig`、`FetchRun`、`SourceVersion`、`ProcessingResult`。来源只能通过内置白名单初始化；界面可停用来源。原文版本、候选和获取日志只读；待处理候选可对照当前赛事字段差异后采纳或拒绝，不能任意编辑 JSON 冒充解析结果。需要修正规则时修改适配器和规则版本并重新采集。

## 持续运行与边界

Windows 调度调用上述 `scheduled` 命令，每 6 小时一次；安装方法见 [本机定时任务](maintenance.md)，实际启用状态见 [团队进度](progress.md)。电脑关机或数据库不可用时不会采集。服务器部署后可用等效 systemd timer，不必先引入 Redis 队列。

HTTPX 限连接超时 5 秒、读取超时 15 秒，最多 3 次尝试、3 次重定向，单页解压正文上限 2 MB，同站请求至少间隔 1 秒。每跳重新检查来源白名单，遵守 robots；原文当作数据处理，不执行脚本。

连接固定到已校验的公网 IP，并保留原域名的 Host 和 TLS SNI/证书校验，避免 DNS 二次解析重绑定。本机若因 TUN 代理得到虚拟地址，向固定 `https://1.1.1.1/dns-query` 查询公开域名，再连接返回的公网 IP；仍不允许本机、私网或元数据地址，不关闭 TLS 验证。技术依据见 [HTTPX SNI 扩展](https://www.python-httpx.org/advanced/extensions/#sni_hostname)。

没有模型密钥也能完成整条规则采集链路；本轮不会调用付费模型。公众号协调同步、PDF 解析、更多赛事站点和自动判断复杂规则冲突需要单独扩展，不能简单添加一个任意网址就宣称已接入。

## 验证方法

```powershell
.\.venv\Scripts\python.exe manage.py test ingestion --noinput
```

测试覆盖文章范围隔离、届次和季节、缺失值、官网链接发现、URL/重定向/robots 限制、固定公网 IP 和 TLS 域名、有限重试和正文上限、跨连接来源互斥、版本去重、不可变历史、候选采纳幂等、重要变更待复核、人工修订保护、事务回滚和失败保留旧数据。测试 HTML 是构造样本，仅存在测试库；不能作为网站公开赛事导入。真实官网只读验证与正式库导入分别记录。

NCDA 专项测试另覆盖合并行、征稿入口范围、页脚年份隔离、跨年度编码、作者与教师口径、投稿/报名分离、多日期歧义、截止更新待复核以及重复运行不刷新赛事公开时间。
