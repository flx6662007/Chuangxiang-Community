# 人工验收

这份清单用于三人在各自电脑确认当前免费开发版。**普通页面不展示仓库自带的虚构赛事，先按[采集说明](ingestion-implementation.md)导入真实官方通知；测试夹具仍只在隔离测试库使用。验证码只在后端终端显示，不会发到真实邮箱。** 不需要服务器、域名、SMTP 账号或模型充值。组队检查另见[前端实现](frontend-implementation.md)与[组队接口](api-teams.md)。下文旧样例相关步骤只供隔离环境回归。

## 启动

首次安装、数据库配置和迁移先按 [后端开发](backend-development.md) 完成。已准备好环境的电脑，确认 PostgreSQL 启动后，开两个终端，分别从仓库根目录执行：

```powershell
# 终端一
Set-Location .\backend
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

```powershell
# 终端二
Set-Location .\frontend
npm.cmd run dev
```

浏览器打开 <http://localhost:5173/>，不要把后端 `8000` 当作网站首页。账号检查全程保持相同地址和浏览器窗口。前端若改用其他端口，须同步可信来源；默认 5173 可直接按样例配置使用。

## 赛事页面

| 操作 | 应看到什么 |
| --- | --- |
| 打开首页，进入赛事列表 | 卡片从本机数据库读取真实赛事，有标题、简介、日期与来源；数量以本机已完成的采集为准 |
| 搜索页面中已有标题的一部分 | 只显示匹配结果；搜索不存在的关键词时提示暂无结果 |
| 清空搜索，有多页时点击下一页再返回 | 页码和内容变化，数量正确；不足一页时不出现无效翻页 |
| 点击一张卡片进入详情 | 展示资格、报名、时间与来源链接；点击返回列表保留搜索/页码 |
| 直接刷新详情页 | 仍能打开相同详情，不出现前端路由 404 |
| 查看只有日期、没有具体时刻的赛事 | 明确显示未注明时刻，不补成午夜或 23:59 |
| 访问 `/competitions/999999999` | 显示赛事不可访问，而非空白页面或私有信息 |
| 暂停后端，刷新列表；再恢复并重试 | 先有错误提示，恢复后可重新加载；测试后保留正常启动状态 |

赛事应可跳转到官方原文；只有作品提交截止的赛事显示“作品提交截止”，不将其改称报名截止。草稿与下架是否被隐藏还可在下方后台检查中验证。

## 账号与验证码

只在本机 Console 邮件配置下，用独立的开发测试邮箱标识注册，例如自己约定的 `本机测试标识@tongji.edu.cn`；选用便于识别的英文标识与独立测试密码。不要输入他人的真实联系方式。若以后改成真实 SMTP，必须改用自己实际掌控的收件邮箱。

| 操作 | 应看到什么 |
| --- | --- |
| 在“我的账号”尝试非学校域名注册 | 被拒绝；改用学校域名及符合强度的测试密码后可注册 |
| 注册成功查看状态 | 已登录但邮箱仍“待验证”，尚不具备发布/申请账号资格 |
| 点击发送验证码 | 页面提示已发送；后端终端打印对应收件标识、主题和验证码；真实邮箱不会收到 |
| 先输入一个错误码，再输入终端中的最新正确码 | 错误码显示提示；正确码成功后显示已验证 |
| 填写微信号或手机号，保存后刷新 | 本人资料保留；满足账号门槛后可继续组队流程，具体还需检查赛事、名额和队伍状态 |
| 退出账号后刷新，再用原账号登录 | 退出后需要登录；重新登录可读到原资料与核验状态 |
| 退出后用同一邮箱重复注册 | 不覆盖已有密码和资料，提示已存在或输入错误 |
| 点击忘记密码，提交刚注册的邮箱 | 页面进入验证码与新密码流程；从后端终端复制本次邮件完整验证码 |
| 完成密码重置后登录 | 需要重新登录，新密码可用、旧密码不可用；不要只看网络面板的 401 就认定重置失败 |

验证码过期、重复使用、尝试次数与服务端限流已有自动化覆盖。要手工补测，可用新的本机测试账号：发送后等待至少 60 秒再重发，旧码应失效；新码从首次发送起仍只在 10 分钟内有效。不要为验收连续制造大量请求；触发限流后按提示等待。

验证码在发起流程的会话内使用，切换无痕窗口或另一浏览器不能接续该轮。密码找回码格式与学校邮箱核验码可能不同，复制邮件中的完整值。

## 管理后台

在 `backend` 执行 `manage.py createsuperuser` 创建自己的本机管理员，完整命令见开发说明。不要尝试用 15 个禁用样例账号登录，也不要共享管理员密码。

进入 <http://127.0.0.1:8000/admin/>，用这个管理员登录。新增内容都加“人工验收”字样，避免与已有样例混淆。下面只操作自己本次建立、没有关联队伍的测试赛事。

| 操作 | 应看到什么 |
| --- | --- |
| 添加一个测试赛事并保存 | 默认是草稿；公开列表搜索不到它 |
| 在赛事来源中为它添加原文链接，设置主来源 | 来源与赛事关联；填写真实可核对内容后才能勾选“已打开原文确认” |
| 测试缺少已核验主来源时发布 | 后台给出原因，不能直接进入公开列表 |
| 完善来源与字段，在赛事列表选择核验发布动作 | 成功后前台可查询，详情有来源；后台记录核验与发布时间 |
| 下架时不填原因 | 被拒绝，原公开状态保持 |
| 填写测试下架原因再下架 | 前台列表不再显示，原详情地址不可公开访问 |
| 对草稿或已下架测试赛事更换主来源 | 新来源成为唯一主来源，旧主来源自动取消；重新核验后再发布 |
| 查看用户和邮箱核验管理 | 使用邮箱和系统代号，没有用户名必填项；邮箱核验记录只读，不能直接勾选验证成功 |

如果只是检查表单，不要对未打开的来源勾选“已核验”。可以使用本人编写、明确标记的测试通知及其受控地址；没有可核验来源时停在发布被拒绝步骤即可，完整来源/发布规则由自动化测试覆盖。不要把虚构内容迁移到未来正式数据库。

已关联队伍的赛事下架会停止招募及未完成入队流程，保留正式成员关系和历史记录；相关事务已有自动化覆盖。需要手动复测时使用隔离测试库，不对真实赛事和队伍做破坏性操作。

## 举报、申诉与人工栏目

| 操作 | 应看到什么 |
| --- | --- |
| 未登录时查看赛事或招募详情 | 举报入口提示登录，不能直接提交 |
| 用已登录但未核验或受限的测试账号举报 | 可以提交；举报不自动下架内容或处罚账号 |
| 打开“我的账号 → 举报与申诉” | 只显示本人记录；申诉目标限本人有权申诉的处理记录 |
| 退出后回到原页面，再换另一个账号 | 旧记录被清除；不能看到其他账号记录 |
| 管理员处理记录 | 使用专用复核表单；不能审核本人提交或复核自己作出的原处理；普通详情页不能直接改结论 |
| 查看首页创享快讯 | 未录入时显示首期筹备中的空状态；手动内容维护见 `frontend/src/data/editorial.js` |
| 查看本科科研线索 | 展示官方来源、原信息日期与核查日；历史招募不冒充当前名额已确认 |

实际治理页面验收见[举报申诉记录](governance-acceptance-2026-09-26.md)，组队流程见[双账号浏览器记录](browser-acceptance-2026-09-26.md)。快讯和科研暂没有在线编辑后台。

## 记录结果

每人记录：代码提交号、日期、电脑环境、通过的步骤；失败时写操作、预期、实际结果及去除隐私的截图。不要粘贴密码、验证码、邮箱完整地址、配置文件或数据库备份。把问题交给对应负责人复现，不直接删除数据库或迁移文件。

本机验收通过后，再按 [部署说明](deployment.md) 验证目标 Linux 环境、HTTPS 和真实邮件。当前验收不能证明其他网络能访问，也不能代替 SMTP 收件检查。
