# 学校目录与官网监测

更新：2026-09-28。本轮以《同济大学本科生学科竞赛目录（2026版）》的 **255项赛事** 为范围，包含理工、人文、语言、经管、艺术等全部学科，不再按理工类筛选，也不运行52jingsai、赛欢或赛氪发现管道。

255是学校目录条目数，**不是已经成功采集、仍可报名或已经发布的赛事数量**。一项赛事系列可以对应多个届次、赛道与官网入口；未确认官网、网站暂不可达及只有往届通知的条目均保留说明。实际运行数量与上传状态见[团队进度](progress.md)。

## 数据怎样流转

```text
学校目录：确定允许收录的赛事系列
  → 首次核对官网/主办方通知及关联依据
  → 登记明确域名白名单
  → 定时读取官网入口、导航中的通知列表
  → 跟进名称匹配的通知，保存正文、附件链接及版本
  → 后台核对届次、赛项和关键规则
  → 接入已验证的字段适配器，经过受控采纳
  → 正式赛事关联学校目录，前台读取已保存数据
```

官网监测与正式发布是两个步骤。通用监测只保存后台原文，没有“一键把任意网页变成公开赛事”的功能。已有官方适配器继续按各自的提取、校验和变更保护规则工作。

## 目录与官网的边界

目录配置保存在 `backend/competition_catalog/data/tongji-2026.json`，只包含目录编号、名称、等级、赛事级别、责任学院及核查后的来源信息，不导出原文件中的负责人姓名和工号。学校目录依据见[官方发布页](https://qdc.tongji.edu.cn/info/1035/1791.htm)。

官网入口须能由主办单位、承办单位、授权赛事平台或学校正式通知证明。学校自己举办的赛事可以使用主办学院的通知；其他高校的转载、参赛报道或聚合站只适合作为核查线索，不能自行升级为赛事官网。

来源说明会区分独立赛事站、主办方通知和待确认项目。找到往届通知可以证明历史来源，但不能证明2026年已经开赛或仍接受报名。赛事改名、分赛道和不同年度也须单独确认。目录等级不等于每个赛道、每种奖项都能按该等级获得学校认定；具体以学校当年规定为准。

## 当前自动做什么

| 功能 | 已实现的范围 |
| --- | --- |
| 官网获取 | 只访问登记域名；复用现有安全HTTP客户端，遵守robots、请求间隔、超时、大小和重定向限制 |
| 后续发现 | 从非赛事专站的页面导航选择最多1个通知列表；从入口和列表跟进标题匹配的赛事通知 |
| 抓取上限 | 每入口默认最多3页，包含入口、列表和详情的共同预算；不遍历整站 |
| 失败轮换 | 新页面与已知详情按上次尝试时间排队，失败链接不会一直占用详情复查名额 |
| 原文保存 | 保存标题、正文、原文地址、明确发布日期、附件链接和读取时间 |
| 版本去重 | 正文内容哈希去重；内容A→B→A时复用A原文并更新当前版本指针，保留历史 |
| 并发控制 | 按来源互斥；拿锁后重新检查入口和目录是否仍启用 |
| 失败记录 | 记录部分成功、失败原因与下次检查时间；网络失败不删除既有原文或正式赛事 |

普通复查间隔为6小时。整入口失败后按12、24、48、72小时逐步退避，最高72小时；部分页面成功时仍按6小时复查。每轮共享相同域名配置下的成功响应，避免同一入口被不同目录条目重复请求。

仅在发布日期有明确标记时保存发布日期；不拿页脚年份、报名日期或抓取时间替代。标题含往年年份时标记往届；标题没有年份时，明确的往年发布日期也用于历史提示。该提示不等于已经识别报名期限，当年内容也可能早已截止。

## 后台能看到什么

入口：Django管理后台 `/admin/competition_catalog/`。需要有效管理员身份及对应模型查看权限；本轮管理页是只读页，不自动给账号授权。

| 记录 | 用途 |
| --- | --- |
| `CatalogEntry` | 学校目录条目、原名、等级、别名和是否纳入当前范围 |
| `OfficialSite` | 官网入口、关联依据、获准域名、最近状态及下次检查时间 |
| `OfficialNotice` | 入口快照或通知正文、版本、附件链接、发布日期和最近读取时间 |
| `MonitorRun` | 一次监测的成功页数、新增版本、未变数量和错误 |
| `CatalogBinding` | 正式赛事与学校目录条目的明确关联依据 |

原文处理状态包括：

- `pending`：待提取核对。只说明有原文，**不表示报名中**。
- `attachment`：正文较短且附有文件，关键规则可能在附件中。
- `historical`：有明确往年依据，保留为历史资料。

运行状态包括成功、仅入口快照、部分成功、失败、中断；锁竞争或入口已停用会跳过。获奖公示、比赛结束报道可以归档，但不会因出现未来公示日期而开放报名或组队。

原文、后台备注与运行信息没有新增公开HTTP接口，也不自动进入AI检索。命令日志只输出编号、状态、数量和错误摘要，不输出整篇正文。公开网页中自带的联系信息可能留在受权限保护的原文中，不因此同步到前台卡片。

## 尚未自动完成的部分

1. **未知官网首次确认。** 不能只按名称搜索到一个域名就自动信任；网站更换域名也需重新核查。
2. **任意版式的字段提取。** 主办、资格、人数、截止日期等仍需要明确原文和适配规则；不能套用别届信息。
3. **PDF、图片、压缩包和动态页面。** 当前通用监测只解析公开HTML/纯文本；保存附件链接不等于已读取附件。登录、验证码和网站限制不绕过。
4. **全年完整历史与所有通知。** 仅有限页数、明确导航和名称匹配；没有合适列表、标题简称未加入别名或网站使用动态加载时会遗漏，需补入口或专用适配器。
5. **自动发布和AI理解。** 通用原文监测不生成公开赛事、不自动开招募，也不调用模型；只有经过验证的正式采集流程才能采纳字段。

首次确认规则属于哪一届、哪一赛项后，再判断有无资格、参赛形式、学生人数和期限证据。投稿截止不得冒充报名截止，教师人数不得当作学生人数。缺失或冲突留待处理，重要条件变化不能静默覆盖人工修订或旧年度队伍历史。

## 初始化与手动运行

在 `backend` 目录执行：

```powershell
# 按版本化配置登记目录与已核实官网，不创建账号或授予权限。
.\.venv\Scripts\python.exe manage.py init_competition_catalog

# 读取启用且到期的官网入口。
.\.venv\Scripts\python.exe manage.py sync_competition_catalog

# 单独复查一个目录条目，最多3页。
.\.venv\Scripts\python.exe manage.py sync_competition_catalog --code 2026171 --force --max-pages 3
```

`--code` 可重复指定；`--limit` 为1～500个入口，默认300；`--max-pages` 为每入口1～10页，默认3。`--force` 只忽略下次检查时间，不绕过停用状态、域名白名单、robots或访问限制。

重复初始化不删除原文、正式赛事及组队数据，也不擅自恢复已经暂停的入口。核查后从版本清单移除的旧官网会停止轮询，历史审计记录仍保留。

Windows维护脚本已串联原有 `sync_competitions` 和新的 `sync_competition_catalog`，单个流程失败仍执行另一个流程，并保留非零汇总退出码。任务依赖本机开机、所需登录状态、PostgreSQL和网络；定时触发不等于网站全天在线。部署与日志位置见[运维说明](maintenance.md)。

## 前台展示与验收

启用学校目录范围后，公开列表只展示已经与有效目录条目关联的正式赛事；不会为了填满255项而生成空卡片。范围之外的既有记录不被删除，既有队伍和详情按原业务权限处理。

分别核对“目录条目数、已确认入口数、实际成功读取数、有效通知数、已发布赛事数”。验证时至少检查：

- 原始目录仍为255项，学科范围完整且不含负责人私人字段。
- 未确认、失败和只有往届材料的来源保留真实状态。
- 从真实列表发现新通知；同一正文重复读取不增加版本。
- 跨域、危险地址、失效来源和没有权限的后台访问被阻止。
- 获奖公示与原文归档不会新增正式赛事或开放招募。
- 正式赛事字段来自相应届次原文，前端卡片只展示已保存的有效数据。

详细字段提取与受控采纳见[采集实现](ingestion-implementation.md)，来源进展见[来源清单](competition-sources.md)。本轮代码不需要AI密钥或GPU，后续AI可辅助提取，但仍须经过来源和业务校验。
