# 界面与功能修订方案

修订日期：2026-09-26。依据团队提供的蓝白风格界面参考图、当前代码及已确认的产品规则。本文件决定页面如何组织，不以参考图中的演示数字、文案或按钮作为已经实现的功能。

## 本次决定

采用参考图的浅蓝背景、白色卡片、深蓝标题、蓝色操作按钮、顶部导航和清晰分区。继续只做电脑端网页，适配常见电脑窗口及浏览器缩放。平台名称沿用“创享平台”。

当前先改现有首页、赛事列表、赛事详情与账号页；后续以同一套组件接入团队广场。前后端继续使用现有 Vue 与 Django 工程，数据表不因换界面而整体重建。真实 SMTP 接入暂停，已有会话与权限保留，开发使用测试账号及控制台验证码。

## 需要调整的界面细节

1. 首页“200+赛事、5000+学生、1000+项目、50+机构”等数字删除。将来确有统计需求时再定义口径并从数据库读取，不用演示数值充当运营成果。
2. “近期热门赛事”改为“最新赛事”。当前按平台首次发布时间排序，没有访问量或热度算法。
3. 首页搜索先限定为赛事名称或关键词。团队、科研等搜索分别在所属栏目提供，不展示尚未支持的全站搜索提示。
4. 赛事详情的“立即报名”改为“查看官方报名信息”，有明确报名 URL 才跳转该地址，否则展示官方通知来源。平台不代办报名，不把点击链接记作“已参赛”。
5. 赛事详情使用简介、参赛要求、时间与校内安排、官方来源等已有字段分区。赛程、奖项、手册和历届回顾仅在有来源和维护方式时提供，缺失内容不编造。
6. “报名中”“进行中”不能仅根据年份或抓取时间生成。截止仅有日期、起始时间未知或信息不完整时直接显示时间原文及“未注明”等提示，平台招募状态与官方报名状态分开。
7. 讨论区、自由发帖、站内私聊、人物专访投稿、开放经验分享暂不建设。系统通知只用于申请、修改和成员事件。
8. 团队卡片标题由赛事名称、届次和招募标签组合生成。没有自由队名字段时不把参考图的项目名称输入框直接上线。
9. 招募有效期沿用 3／7／14 天，并取所选期限与赛事平台招募截止的较早者；编辑不延长有效期。基础要求、每周投入、协作方式及条件性校区规则沿用既定模板。
10. 公开卡片、页面源码及公开 API 都不包含学生联系方式；仅在授权后由独立接口返回。不能靠前端隐藏已经下载的私有数据。

## 页面和数据如何连接

赛事采集在后台定时执行，取得原文后保存来源版本、解析候选、校验并按规则采纳。用户浏览时由 Django 查询已保存赛事，Vue 把 JSON 数据放进现成卡片；不等待爬虫或 AI 制作页面。

组队业务沿用“申请 → 招募者接受联系 → 双方获得联系方式 → 自行沟通 → 双方确认正式入队”。提交申请和接受联系都不占名额；入队、修改、过期、退出及解散由后端统一检查与保存。

## 前后端交接

| 负责人 | 本次可交付内容 | 后续 M1 交付 |
| --- | --- | --- |
| 前端 | 首页、赛事列表、详情、账号的统一视觉；保留现有搜索、分页、登录和错误提示 | 团队广场、固定模板、我的组队、通知页面，对接已确定接口 |
| 后端 | 本文和后端实施方案；保留现有业务，不为视觉改版变更认证 | 招募与申请事务、授权联系、入队及完整状态处理；真实来源采集命令和调度 |
| 数据库 | 确认页面所需数据能否从现有字段表达 | 核对唯一约束、名额并发、内容版本及去重；确有缺项才补迁移 |

组队完整状态应包含卡片编辑后挂起及重新确认、满员与过期、赛事停招或下架、退出、移除、解散和系统通知。只完成界面或正常路径不能视为已经可以向真实学生开放。

## 验收边界

- 当前视觉改版：现有页面可正常打开；真实 API 数据、搜索、分页、详情返回和账号流程保留；空、错误、加载及长标题可读，没有假统计和不可用入口。
- M1 组队：匿名看不到联系方式；核验门槛有效；同一卡重复申请、同届重复入队和最后名额并发均被正确处理；变更通知和结束规则可复现。
- M1 采集：指定来源可采集；原文无变化不重复入库；同名不同届次分开；抓取失败保留旧内容；记录上次成功时间。每 6 小时是计划周期，关机期间不承诺持续更新。
- M2 与 M3：各自功能完成并验收后再增加入口，不提前展示可点击的空壳页面。
