# 创享平台前端

本目录是电脑端 Vue 3 前端工程，使用 Vite、Vue Router、Axios 和 Element Plus。已接入真实赛事列表、详情和账号接口，支持搜索分页、学校邮箱核验、联系方式维护及密码找回。组队业务尚未开放。

## 环境与启动

- Node.js 20.19+ 或 22.12+
- npm（随标准 Node.js 安装提供）

在 `frontend/` 目录执行：

```powershell
npm ci
npm run dev
```

浏览器打开终端显示的本地地址（默认 `http://localhost:5173/`）。生产构建可执行 `npm run build`，本地预览构建结果可执行 `npm run preview`。

## 页面与人工检查

| 页面 | 默认开发地址 | 当前内容 |
| --- | --- | --- |
| 首页 | `http://localhost:5173/` | 平台介绍和赛事入口 |
| 赛事列表 | `http://localhost:5173/competitions` | 接口读取的赛事卡片（当前为虚构样例）、搜索、每页 20 条和分页 |
| 赛事详情 | `http://localhost:5173/competitions/<id>` | 参赛要求、日期、报名方式和通知原文 |
| 我的账号 | `http://localhost:5173/account` | 注册登录、学校邮箱核验、本人联系方式、退出和密码找回 |

所有页面共用顶栏，可通过“首页”“赛事列表”“我的账号”导航切换；也可以直接输入赛事列表地址或在该地址刷新。若默认端口被占用，以终端显示的实际地址为准，在其后加 `/competitions`。开发期间保持终端运行，按 `Ctrl+C` 停止服务。

赛事页面需要后端和数据库可用。先按照 [后端启动说明](../docs/backend-development.md) 迁移并导入开发样例，再启动后端和前端。样例是虚构开发数据，不能作为真实赛事发布。

1. 打开列表，检查卡片来自数据库；搜索已有标题和不存在的关键词，分别检查结果与空状态。
2. 点击卡片进入详情，核对截止日期、参赛要求和原文链接；返回列表应保留搜索词和页码。
3. 数据超过 20 条时检查上下页；可直接访问 `?page=999999` 检查无效页提示及返回第一页。
4. 停止后端，刷新列表检查错误提示；恢复后端后点击“重新加载”。
5. 检查仅有日期的字段显示“未注明时刻”，不自行补为当天午夜或 23:59。
6. 浏览器刷新详情地址应正常；不存在或下架的赛事应提示不可访问。

账号检查：

1. 使用开发测试学校邮箱注册。注册后可登录，但邮箱状态仍应为“待验证”；非 `@tongji.edu.cn` 邮箱应被拒绝。
2. 点击发送验证码。开发配置使用 console 邮件后端时，在后端终端中读取验证码；不要把开发账号、密码或验证码提交到 GitHub。真实收信需配置 SMTP 后再验收。
3. 输入错误验证码检查提示，再输入当前有效验证码，核验状态必须以服务器返回结果为准。重用或过期验证码应拒绝。
4. 保存微信号或手机号，刷新后检查资料保留；退出再登录，确认需要重新取得会话，且浏览器 localStorage 不保存登录令牌。
5. 退出后点击“忘记密码”，在同一浏览器页面发起、填写邮件验证码并设置新密码。新密码应能登录，旧密码应失败。
6. 检查重复点击被暂时禁用，验证码重发有等待提示；本次邮箱验证从首次发送起 10 分钟有效，重发不延长有效期。服务器仍独立执行频率和尝试次数限制。
7. 在另一标签页退出后，回到旧账号页保存联系方式，页面应检查会话、清空原资料并回到登录表单，不能误报为验证码频率限制。

`npm test` 检查网址协议、时间格式、CSRF 读取和认证响应状态边界；`npm run build` 检查生产构建。它们不能替代上述浏览器联调。正式部署时，Web 服务器须将前端页面路径回退到 `index.html`，以支持 history 路由刷新；Vite 开发服务器已支持。

## 目录

```text
src/
├── api/        # Axios 实例和按功能划分的请求函数
├── components/ # CompetitionCard 等可复用组件
├── layouts/    # 页面共用布局
├── mocks/      # 队友第一轮静态演示样例，仅留作开发参考
├── router/     # 路由定义
├── styles/     # 全局基础样式
├── utils/      # 安全网址和赛事日期显示
├── views/      # 路由对应的视图
├── App.vue     # 应用根组件
└── main.js     # 应用入口与插件注册
```

开发环境中，以 `/api` 开头的请求由 Vite 转发到 `http://127.0.0.1:8000`。如需修改后端地址，可复制 `.env.example` 为 `.env.local`，设置 `DEV_PROXY_TARGET`；Axios 的基础路径由 `VITE_API_BASE_URL` 控制，默认 `/api/v1`。本机配置不要提交。接口以 [docs/api.md](../docs/api.md) 为准。

列表请求 `GET /api/v1/competitions/?page=1&page_size=20&search=关键词`，详情请求 `GET /api/v1/competitions/<id>/`。切换搜索、页码或赛事时取消旧请求，并通过请求序号避免旧响应覆盖新页面。前端只渲染 JSON 数据，不在打开列表或详情时调用 AI。

已合入队友的 `CompetitionCard.vue` 和 Element Plus 分页组件。卡片读取接口的 `primary_source` 显示原文与来源发布日期；报名截止保留来源时区和日期精度。列表接口不包含作品提交截止，卡片提供详情入口，由详情页展示该字段。分页点击会请求对应页接口，不是对本地数组切片。

`src/mocks/competitions.js` 保留队友第一轮的 12 条虚构演示数据，当前页面不导入、不使用这份 mock；其旧字段形状不能直接当作正式接口契约。后端失败时显示错误与重试入口，不会自动换成静态样例。当前数据库开发样例也都是虚构内容，真实赛事仍需录入与核验。

账号使用服务端 Session Cookie，写请求每次从当前 `csrftoken` cookie 读取 `X-CSRFToken`，不会缓存登录前的旧值，也不使用 localStorage 储存会话。认证入口 `VITE_AUTH_BASE_URL` 默认 `/api/auth/browser/v1`，开发时和 `/api/v1` 一起走 Vite 同源代理；生产部署也按同源入口配置。不要简单改为任意跨域地址，跨域 Cookie 与 CSRF 需另行设计。

allauth 在“未登录”“已退出”“密码重置进行中/完成”都可能返回 401；`src/api/accounts.js` 进一步检查 `meta.is_authenticated` 和 `data.flows`，避免把失败误判为成功。账号状态与邮箱是否验证始终重新读取 `/api/v1/accounts/me/`。
