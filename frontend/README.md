# 创享平台前端

本目录是电脑端 Vue 3 前端工程。当前包含工程入口、路由、统一 Axios 请求入口、Element Plus、基础布局及可访问的赛事列表页面骨架。赛事列表目前显示静态占位内容，尚未接入数据、卡片和分页；账号等业务页面待后续开发。

## 环境与启动

- Node.js 20.19+ 或 22.12+
- npm（随标准 Node.js 安装提供）

在 `frontend/` 目录执行：

```powershell
npm install
npm run dev
```

浏览器打开终端显示的本地地址（默认 `http://localhost:5173/`）。生产构建可执行 `npm run build`，本地预览构建结果可执行 `npm run preview`。

## 页面访问与 R1-F1 检查

| 页面 | 默认开发地址 | 当前内容 |
| --- | --- | --- |
| 首页 | `http://localhost:5173/` | 工程欢迎页和“查看赛事列表”入口 |
| 赛事列表 | `http://localhost:5173/competitions` | 页面标题及“赛事内容即将上线”占位区域 |

两个页面共用顶栏，可通过“首页”和“赛事列表”导航切换；也可以直接输入赛事列表地址或在该地址刷新。若默认端口被占用，以终端显示的实际地址为准，在其后加 `/competitions`。开发期间保持终端运行，按 `Ctrl+C` 停止服务。

这两个页面不发送业务请求，无需后端或数据库也能打开。R1-F1 的本地检查包括：依赖安装成功、开发服务启动成功、导航可进入赛事列表、直接访问和刷新赛事列表正常、`npm run build` 通过。队友首次运行时仍需在自己的电脑按上述步骤验收。

赛事卡片、虚构数据及分页属于 R1-F2；加载、无数据、请求失败和真实接口联调属于 R1-F3。当前静态占位内容不代表后端已返回空列表。正式部署时，Web 服务器还需将前端页面路径回退到 `index.html`，以支持 history 路由的直接访问和刷新；Vite 开发服务器已提供该支持。

## 目录

```text
src/
├── api/        # Axios 实例和按功能划分的请求函数
├── layouts/    # 页面共用布局
├── router/     # 路由定义
├── styles/     # 全局基础样式
├── views/      # 路由对应的视图
├── App.vue     # 应用根组件
└── main.js     # 应用入口与插件注册
```

开发环境中，以 `/api` 开头的请求由 Vite 转发到 `http://127.0.0.1:8000`。如需修改后端地址，可复制 `.env.example` 为 `.env.local`，设置 `DEV_PROXY_TARGET`；Axios 的基础路径由 `VITE_API_BASE_URL` 控制，默认 `/api/v1`。本机配置不要提交。当前 `src/api/health.js` 只封装已有的健康检查接口，后端业务接口尚未实现，新增业务请求前须与后端确认接口契约。
